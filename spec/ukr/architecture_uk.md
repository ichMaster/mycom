# Архітектура — MyCom

> Українська копія [architecture.md](../architecture.md). Канонічна версія — англійська; у разі розбіжностей вона має пріоритет.

## Огляд

Дві незалежні осі. **Ядро ортодоксального ФМ** росте: панелі й навігація → виділення і персистентність → файлові операції → командний рядок і консоль → переглядач і редактор. **AI-шар** росте окремо: палітра команд → контекстний чат і розумне виділення → вбудований агент Claude Code. Їх пов'язує асинхронне ядро з одним правилом: **єдиний цикл подій володіє всіма змінами UI** (правило єдиного записувача — урок відкладених комітів `Manager::Commit` у FAR, перекладений на Python/Textual). Довга робота виконується у workers; workers ніколи не торкаються віджетів напряму; результати повертаються в цикл подій.

Три архітектурні правила несучі й не підлягають перегляду:

1. **Жодної втрати даних.** Вихідні файли недоторканні, доки операція повністю не завершиться; скасування завжди безпечне.
2. **Офлайн-деградація.** AI-шар опціональний під час виконання: немає ключа → діалог налаштування; жодного мережевого трафіку, доки AI-функцію явно не викликано.
3. **UI керується даними.** Клавіші, меню, підписи панелі F-клавіш, кольори, маски, підсвічування та асоціації — це дані (конфіг, тема, реєстр), ніколи не хардкод у віджетах.

## Компоненти

- **Оболонка застосунку (`app.py`).** Textual `App`: керування екранами (панелі ↔ консоль ↔ переглядач ↔ редактор), глобальна маршрутизація клавіш через реєстр клавіатурної мапи, старт/зупинка (флаш стану).
- **Реєстр клавіш і команд (`keymap.py`).** Одна структура даних: команда → клавіша(і) → контекст → підпис. Живить прив'язки Textual, панель F-клавіш і (v1) меню F9 — тож підписи й меню ніколи не розходяться зі справжніми прив'язками. Конфіг `[keybindings]` накладається зверху.
- **Панелі (`panels/`).** Двопанельна система: список теки з режимами перегляду (Brief/Full/Wide), сортуванням, швидким пошуком (v1), підсвічуванням (v1); модель виділення; рядок шляху і підвал панелі. Панелі — чисті споживачі снапшотів `fs`, вони ніколи не торкаються диска напряму.
- **Файлова система (`fs/`).** Сканування тек у незмінні снапшоти `FileEntry`, обробка stat/симлінків, людське форматування, (v1) автооновлення через watchdog, що живить панелі крізь цикл подій.
- **Рушій файлових операцій (`fileops/`).** Конвеєр «план → виконання» для copy/move/delete/mkdir/rename: асинхронний worker обходить і виконує план, звітуючи `OpProgress` діалогу прогресу та радячись із `ConflictPolicy` (шестиваріантний діалог зі «липкими» відповідями All) і, у v1, з `RecoveryPolicy` (Retry/Skip/Skip All/Cancel). Скасування на межах чанків; крос-девайс переміщення видаляє джерело лише після верифікованої копії.
- **Консоль (`console/`).** Командний рядок під панелями, cd-sync (в обидва боки) і PTY-запускач: команди виконуються у псевдотерміналі з passthrough у стилі `script` — дитина володіє справжнім терміналом (vim/htop працюють), а вивід tee-каналом іде в обмежений кільцевий буфер для виклику через `Ctrl+O`. `cd` перехоплюється, ніколи не спавниться.
- **Переглядач (`viewer/`).** Лише читання, віконний (mmap/чанки — ніколи файл цілком): миттєве відкриття за будь-якого розміру; перемикач переносу; v1 додає hex-режим, кодування, пошук, підсвічування синтаксису і режим quick view.
- **Редактор (`editor/`).** На базі Textual `TextArea` із запобіжниками довіри (зміни-при-закритті, зовнішні-зміни-при-збереженні, збереження EOL) і запасним виходом `$EDITOR` (suspend → запуск → resume → refresh). Свідомо скромний: 20k рядків редактора FAR — не наша планка.
- **Діалоговий набір (`widgets/dialog.py`).** Єдиний модальний рушій (рамка, заголовок, поля, кнопки, гарячі літери, стекування), на якому побудовано кожен діалог. «Нуль ad-hoc модального коду» — аудитований інваріант.
- **Тема (`theme.py` + файли тем).** Увесь колір живе в даних теми; за замовчуванням — «Far classic», знята з `colormix.cpp`/`palette.cpp` FAR (таблиця нижче); truecolor із таблицею відкату до 256 кольорів.
- **Стан (`state.py`).** Одна база SQLite (WAL) для стану виконання та історій; TOML (`config.py`) для авторських налаштувань. Див. §Персистентність.
- **Платформний шар (`platform/`).** Єдине місце OS-залежного коду: розташування/монтування, смітник, буфер обміну, keychain, відкриття за асоціацією, специфіка conpty. POSIX — першокласний; Windows — за залишковим принципом.
- **AI-модуль (`ai/`).** Шов `LLMClient` над Anthropic SDK, палітра команд і (v1) чат-сайдбар, пояснення/підсумовування, розумне виділення, вартісні запобіжники. Див. §AI-шар.
- **Інтеграція Claude Code (`claude_code/`).** Три яруси: запуск через suspend/attach (v0), headless-запуск `claude -p` (v1), вбудовування Agent SDK із TUI-діалогами дозволів (v1). Див. §Інтеграція Claude Code.
- **Логування.** Структурований `logging` з v0.1, конфігурований через env — рятівна нитка для налагодження повноекранного TUI.

## Правило єдиного записувача

Цикл подій Textual — єдиний, хто пише стан UI. Усе повільніше за ~100 мс — сканування величезних дерев, файлові операції, читання PTY, LLM-стріми, сесії агента — виконується у worker (потік або task) і спілкується через повідомлення/`call_from_thread`. Наслідки:

- Рушій операцій звітує прогрес як дані (`OpProgress`); діалог прогресу їх рендерить.
- Спостерігачі ФС, читачі PTY та LLM-стріми — продюсери; віджети — споживачі.
- Скасування — прапорець, що перевіряється на безпечних межах (чанк файлу, крок плану, подія стріму) — ніколи не вбивство потоку.

## Панельна система

Панель рендерить незмінний снапшот списку: `list[FileEntry]` + сортування + режим перегляду + стан фільтра. Дії користувача породжують *наміри* (навігувати, сортувати, виділити); контролер панелі застосовує їх, запитуючи новий снапшот у `fs` і підмінюючи його. Це тримає сортування/виділення чистими та юніт-тестовними, і саме тому автооновлення (v1) дешеве: подія спостерігача просто тригерить той самий шлях підміни снапшота з правилами збереження курсора/виділення.

**Виділення** — вхідний контракт кожної файлової операції: операції споживають *виділення-інакше-курсор* і знімають виділення з оброблених записів при успіху. `..` невиділюване за інваріантом.

**Режими перегляду** (Brief/Full/Wide) — це визначення розкладки колонок: дані, а не підкласи, — з прицілом на власні колонки у v2.

## Рушій файлових операцій

```
обхід → OpPlan (записи, сума байтів) → worker виконує крок за кроком
                                        │ події прогресу → ProgressDialog
                                        │ конфлікт? → ConflictPolicy (діалог, «липке» All)
                                        │ помилка?  → RecoveryPolicy (v1: retry/skip/…)
                                        └ прапорець скасування на межах чанків
```

Інваріанти: копіювання-на-себе відхиляється на етапі плану; переміщення в межах однієї ФС деградує до `rename()`; крос-девайс = копія + верифіковане видалення; метадані зберігаються через `copystat`; симлінки копіюються як посилання. Рушій вільний від UI — політики інжектяться, тож уся матриця тестується на tmpfs-фікстурах без запущеного застосунку.

## Консоль, PTY і cd-sync

Командний рядок — звичайний віджет Textual; *виконання* — ні. `Enter` віддає термінал дитині через PTY з passthrough (модель `script(1)`): сире проксіювання stdin/stdout дає повну інтерактивність (vim, htop, Ctrl-C дитині), а проксі tee-каналом пише вивід в обмежений кільцевий буфер, що живить виклик `Ctrl+O`. На виході: «Press any key» (коли вивід був), панелі відновлюються й обидві оновлюються.

`cd` ніколи не спавниться: він парситься (лапки, `~`) і застосовується до активної панелі. Prompt завжди показує теку активної панелі — cd-sync це інваріант, а не функція.

## Переглядач і редактор

Контракт переглядача — *миттєво за будь-якого розміру*: віконне читання/mmap, `End` робить seek — файл ніколи не завантажується цілком. Контракт редактора — *довіра*: запобіжник брудного закриття, запобіжник зовнішніх змін, збереження EOL і хвостового переносу, перенаправлення бінарних і >10 МБ у переглядач. Обидва мають власний контекст клавіатурної мапи (підписи панелі F-клавіш перемикаються разом із ними). `$EDITOR` через suspend/resume — постійний запасний вихід і запобіжник розповзання редактора.

## Діалоговий набір і тема

Кожна модалка будується з одного набору: вікно з рамкою, заголовок, вміст, ряд кнопок; фокус `Tab`/стрілками, гарячі літери, `Enter` за замовчуванням, `Esc` скасовує, стекування. Правило аудиту «нуль ad-hoc модального коду» тримає взаємодію однорідною — включно з AI-палітрою і діалогами дозволів агента, які свідомо є звичайними діалогами.

Тема за замовчуванням — точна палітра FAR (джерело: `colormix.cpp`/`palette.cpp`, звірено з живим скриншотом FAR):

| Елемент | Кольори |
|---|---|
| Тло / текст панелі | `#00ffff` на `#000080` |
| Рамки панелей | `#00ffff` на `#000080` |
| Активний / неактивний рядок шляху | `#000000` на `#008080` / `#00ffff` на `#000080` |
| Заголовки колонок | `#ffff00` на `#000080` |
| Рядок курсора | `#000000` на `#008080` |
| Виділені файли | `#ffff00` на `#000080` |
| Теки | `#ffffff` на `#000080` |
| Панель F-клавіш: номер / підпис | `#c0c0c0` на `#000000` / `#000000` на `#008080` |
| Діалоги / поля діалогів | `#000000` на `#c0c0c0` / `#000000` на `#008080` |

Лише простий текст — жодних емодзі та бейджів: `\` позначає теки, `~` — симлінки, пробіл — файли. Усе це живе у файлах теми; нічого — у коді віджетів.

## Персистентність

Два сховища з чітким розділенням:

- **`config.toml`** (авторський, версіонується): overrides клавіш, вибір теми, прапорці поведінки, асоціації, налаштування AI. Читається на старті, застосунок його ніколи не пише.
- **`state.db`** (SQLite, WAL, належить застосунку): шлях/сортування/режим панелей, перемикач прихованих, стан вікна, історії (v1), позиції (v2). Схема версіонується з міграціями; записи з дебаунсом і фінальним флашем на виході; пошкоджена/відсутня БД мовчки перестворюється — старт ніколи не блокується станом.

Облікові дані не живуть у жодному з них: env `ANTHROPIC_API_KEY` або OS keychain.

## Платформний шар

`platform/` — єдиний OS-залежний пакет: монтування/розташування, смітник, буфер обміну (pyperclip + OSC 52 для SSH), доступ до keychain, відкриття за асоціацією, специфіка PTY (conpty на Windows). Усе вище нього платформо-нейтральне. POSIX (macOS + Linux) — першокласний; Windows — за залишковим принципом і йому дозволено відставати.

## AI-шар

```
палітра / сайдбар / розумне виділення / пояснення
            │ (будівник контексту: ОС, shell, cwd, імена виділеного, обрізані списки)
        LLMClient  ←— єдиний шов, що імпортує Anthropic SDK
            │ стрімінг, структуровані відповіді, prompt caching (v1), count_tokens (v1)
        Anthropic API   (модель за замовчуванням: claude-opus-5)
```

Правила, яким підкоряється весь шар:

- **Шов.** Код ядра залежить від `LLMClient`, ніколи від SDK. Тести мокають шов; CI не робить жодного платного виклику.
- **Офлайн-деградація.** Жоден AI-об'єкт не конструюється до виклику AI-функції; неналаштовані точки входу показують діалог налаштування.
- **Підтвердження перед запуском.** Згенеровані команди рендеряться з поясненням і рівнем небезпеки (рекурсивне видалення, `sudo`, `dd`, pipe-в-shell → червоне попередження); виконання лише через явний Run, через той самий консольний конвеєр, що й набрані команди.
- **Структуровані відповіді** для всього, що застосунок споживає програмно (результат палітри, предикати виділення v1) — парсяться й валідуються, ніколи не вишкрібаються regex-ом із прози.
- **Вартісні запобіжники (v1).** Preflight `count_tokens` на великих контекстах; пер-сесійний бюджет із видимим лічильником і жорсткою зупинкою.
- **Контекст мінімальний за замовчуванням.** v0 надсилає імена й обрізані списки, ніколи вміст файлів; сайдбар v1 читає вміст на вимогу з лімітами розміру і кешує статичний префікс через prompt caching.

## Інтеграція Claude Code

Три яруси, що постачаються по черзі та поділяють принцип: *сила агента обмежена явною згодою користувача*:

1. **Suspend/attach (v0.8).** `Ctrl+K` віддає справжній термінал `claude` у теці активної панелі; після виходу TUI відновлюється, панелі оновлюються. Нуль протокольної поверхні — максимум надійності.
2. **Headless-запуск (v1.10).** `claude -p "<задача>" --output-format stream-json` на виділенні/CWD; панель задач рендерить потік подій наживо; результат лягає в переглядач; скасування вбиває групу процесів.
3. **Вбудовування Agent SDK (v1.10).** `query(prompt, options)` з `claude-agent-sdk`, робоча тека прибита до активної панелі; панель транскрипту стрімить текст асистента й активність інструментів; **permission-колбеки SDK показуються як діалоги набору** (дозволити/відхилити, скоуп у межах сесії) — агент нічого не редагує без схвалення. Спостерігачі панелей роблять правки агента видимими в момент появи.

Напрям v2 (панель перегляду diff, менеджер сесій, MCP-сервер, що відкриває стан панелей будь-якому агенту) будується на ярусі 3 і свідомо поза обсягом, доки не вийде v1.

```
├── widgets/          # Діалоговий набір, key bar, спільні віджети

├── claude_code/      # Запускач (v0), headless-запуск + SDK-вбудовування (v1)
└── utils/            # Чисті хелпери
```

Міграція з допівотної кодової бази: `panels/`, `widgets/`, `operations/sort.py` і `utils/fs.py` переносяться (сортування переїжджає в семантику `fs/`/`panels` без змін); `mycom/llm/` і `mycom/plugins/` (порожні каркаси старої концепції) видаляються — систему плагінів замінює рішення про API плагінів у v2, а AI живе в `ai/`. Залежності: `pyte` викидається (модель PTY-passthrough не емулює), `anthropic` ховається за шов, `claude-agent-sdk`, `watchdog`, `send2trash`, `pyperclip`, `charset-normalizer`, `pygments` приходять зі своїми фазами як оголошені залежності або extras.

## Тестування і CI

- **Unit-тести на чистих ядрах:** сортування, маски, інваріанти виділення, будівник плану, стейт-машини конфліктів/відновлення, обробка EOL, класифікатор небезпеки, схеми структурованих відповідей — без Textual.
- **Інтеграційні тести через Pilot:** критерії приймання проганяються натисканнями клавіш (`Pilot.press`), а не викликами методів панелі — урок v0.1: тести повз клавіатуру сертифікують функції, яких не існує.
- **Фікстури файлової системи замість моків** для fileops (tmpfs-дерева, величезні розріджені файли, пастки прав).
- **Жодних платних викликів у CI:** кожен AI-тест іде проти мок-`LLMClient`; кожен тест Claude Code — проти сценарного фейкового бінарника чи мок-транспорту. Прогони на справжньому API та справжньому агенті — ручний передрелізний чекліст.
- **Детермінізм:** інжектовані годинники для логіки дебаунсу/ETA; жодних справжніх sleep у тестах.
- Лінт (`ruff`) і тести — ворота кожного релізу фази; кожна фаза постачає тести, що кодують її DoD (див. [roadmap_uk.md](roadmap_uk.md)).
