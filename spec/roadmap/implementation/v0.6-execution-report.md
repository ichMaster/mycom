## Detailed Results

### MC-036: Viewer engine: windowed/mmap reads, encoding fallback
**Status:** completed · **Commit:** b632325
**Validation:** [x] pytest (19 new) · [x] ruff · [x] py_compile · [x] acceptance criteria

`mycom/viewer/buffer.py`'s `ViewerBuffer` — mmap-backed, no full-file index,
`read_lines_forward`/`read_lines_backward` scan only the requested window. A
real bug was caught and fixed during testing: the binary-detection heuristic
must run *before* the strict-UTF-8-decode check, not after — a NUL byte is
technically valid UTF-8 (U+0000) and would otherwise short-circuit past the
latin-1 fallback the binary case needs. Memory-safety testing had to be
redesigned mid-issue: sequentially paging through an entire 300MB file
legitimately grows the OS's reclaimable mmap page-cache RSS (not a leak) —
the real test for "no unbounded Python-level accumulation" is re-reading the
*same* window thousands of times and confirming RSS stays flat.

### MC-037: Viewer screen: F3, navigation, wrap toggle, status bar, F6→editor
**Status:** completed · **Commit:** 518f41b
**Validation:** [x] pytest (12 new) · [x] ruff · [x] py_compile · [x] acceptance criteria

`mycom/viewer/screen.py`'s `ViewerScreen` wires `ViewerBuffer` into a real,
full-screen (not modal) Textual screen. A real bug was caught empirically
before it ever reached a test: the first draft wrapped the body in a
`VerticalScroll`, whose own built-in `BINDINGS` (up/down/pageup/pagedown/
home/end, for its own scrolling) would have silently hijacked every
navigation key before `on_key` ever saw them — confirmed with a throwaway
smoke script, fixed by dropping the container entirely (the screen manages
its own window by file offset; it never needed widget-level scrolling). `F6`
dismisses with an `"edit"` sentinel the app interprets, rather than the
screen reaching into the editor module directly — avoiding a forward
reference between the two screen modules until MC-039 existed to complete
the hand-off.

### MC-039: Editor screen: F4, TextArea, save/save-as, dirty-close guard
**Status:** completed · **Commit:** 4d3fae5
**Validation:** [x] pytest (14 new) · [x] ruff · [x] py_compile · [x] acceptance criteria

`mycom/editor/screen.py`'s `EditorScreen` wraps a Textual `TextArea`
(`tab_behavior="focus"`, confirmed empirically required — the `"indent"`
variant's own `_on_key` special-cases Escape to move focus instead of
letting it bubble, which would have swallowed the dirty-close guard).
Undo/redo needed no custom code at all — `TextArea`'s own `Ctrl+Z`/`Ctrl+Y`
stack already satisfies the requirement. New `SaveDiscardCancelDialog` (a
third `DialogKit` subclass with three buttons, since `ConfirmDialog`'s
Yes/No is ambiguous between "discard" and "stay"). Completed MC-037's
F6-from-viewer hand-off for real, replacing its interim no-op stub, and
updated that issue's own test to match the real behavior.
