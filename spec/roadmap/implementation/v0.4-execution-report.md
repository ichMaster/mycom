## Detailed Results

### MC-025: Operation engine core: plan/execute/progress/cancellation (+ dead-scaffold cleanup)
**Status:** completed · **Commit:** 095f9a1
**Validation:** [x] pytest · [x] ruff · [x] contracts · [x] acceptance
New `mycom/fileops/` package (plan.py, policy.py, engine.py): `PlanEntry`/`OpPlan`, the six-choice
`ConflictPolicy` seam, `execute_plan`/`execute_move_plan`/`execute_delete_plan` with chunked
cancellation, metadata-preserving copy, verify-before-delete cross-device move. Removed the dead
`mycom/llm/`/`mycom/plugins/` scaffolds. 24 new unit tests.

### MC-026: Conflict resolution dialog (F0.10)
**Status:** completed · **Commit:** 3ae181a
**Validation:** [x] pytest · [x] ruff · [x] contracts · [x] acceptance
`ConflictDialog` (six choices incl. in-place rename sub-mode) and `ConflictDialogPolicy` (the
thread-marshalling adapter — `push_screen` + a manually-resolved `asyncio.Future`, since
`push_screen_wait` requires an active Textual worker context a `call_from_thread` coroutine
doesn't have). Found and fixed a real DialogKit bug: Textual dispatches `on_key` to every MRO
class that defines it, not just the most-derived one — a subclass `on_key` calling
`super().on_key()` double-ran the base handling. Added an overridable `_on_escape()` hook instead;
this also fixed a pre-existing bug where `ProgressDialog`'s `key_escape` no-op never actually
suppressed Esc-dismiss. 10 new tests + 1 regression test.

### MC-027: Copy (F5)
**Status:** completed · **Commit:** 063f967
**Validation:** [x] pytest · [x] ruff · [x] contracts · [x] acceptance
Wires `action_copy` end to end: target dialog, precondition refusal, worker-thread
`execute_plan`, `OperationProgressDialog`, panel refresh + deselect on completion. Found and
fixed two real bugs: `copy_entry` had no guard against src/dst resolving to the same file
(would have truncated the source); `get_selected_files()` iterated a `set` in arbitrary order,
making multi-file operation order (and cancellation outcomes) unpredictable — now sorted. 12 new
integration tests + 2 regression tests.

### MC-030: Delete (F8)
**Status:** completed · **Commit:** 6b8a8d7
**Validation:** [x] pytest · [x] ruff · [x] contracts · [x] acceptance
Wires `action_delete`: the full confirmation ladder (initial, per-non-empty-directory, per-
read-only-file), a progress dialog only for trees ≥20 files, cursor to the next surviving entry
(skipping past rows that are themselves being deleted). Found and fixed a real bug: a declined
read-only-file prompt excludes just that file from the plan, which makes its parent directory's
`rmdir` legitimately fail (not empty) — `execute_delete_plan` now tolerates that instead of
propagating the `OSError` and aborting the rest of the delete. 9 new integration tests + 1
regression test.

### MC-031: Rename (Shift+F6)
**Status:** completed · **Commit:** 862167d
**Validation:** [x] pytest · [x] ruff · [x] contracts · [x] acceptance
New `rename` command on `Shift+F6`; `InputDialog` gained a `select_stem` option (pre-selects the
name minus extension, FAR-convention, dotfiles excluded from the split). `action_rename` reuses
`execute_move_plan` with a single-entry plan — a collision routes through the same
`ConflictDialog` copy/move use rather than raising. 6 new integration tests + 3 unit tests.

## Contract / seam notes
The `fileops/` plan/policy/progress seams (`PlanEntry`, `OpPlan`, `ConflictChoice`,
`ConflictPolicy`, `OpProgress`, `CancelToken`, `ExecutionResult`) are new and already match
`spec/architecture.md`'s anticipated shape — no doc drift. `DialogKit` gained one new overridable
hook (`_on_escape()`) used by `ProgressDialog`, `OperationProgressDialog`, and `ConflictDialog`;
`InputDialog` gained the `select_stem` option. Neither changes any existing dialog's public
construction signature or dismiss values.
