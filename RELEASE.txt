MyCom — Release History
=======================

Version 0.6.1 (2026-08-03)
---------------------------
- HARDEN sweep (end of the v0.1-v0.6 run): fixed the one outstanding deferred MEDIUM finding
  (v0.3 code review #2) — selection is keyed by bare filename only, so refresh_listing() (e.g.
  Ctrl+H, or after an external command completes) now drops a selected name whose entry
  (is_dir, size, modified) changed since the last refresh, closing the gap where an external
  process replacing a selected file with an unrelated same-named file left the new file
  silently selected
- No HIGH findings were outstanding anywhere in the run; all LOW findings remain deferred to
  their documented homes (v1.2, v1.3, polish backlog)

Version 0.6.0 (2026-08-03)
---------------------------
- Viewer (F3): read-only, instant open at any file size — windowed/mmap-backed, never loads a
  file whole; arrows/PgUp/PgDn/Home/End navigate by file offset; F2 toggles wrap, preserving
  position exactly; F6 hands off to the editor at the same file, top of file
- Editor (F4): TextArea-based with full undo/redo; EOL (LF/CRLF, including mixed-dominant) and
  trailing-newline state detected on open and preserved byte-for-byte on save; F2 save, Shift+F2
  save-as; quitting a modified buffer always prompts Save/Discard/Cancel; a file changed on disk
  since it was opened warns before an overwriting save; a binary or >10MB file redirects to the
  viewer instead of being loaded
- Alt+F4 (or config editor.external_default) hands the cursor file straight to $EDITOR instead of
  the built-in editor, via the same App.suspend() mechanism the command line uses
- Code review fixes: unrecognized keys no longer leak from the viewer/editor into panel-level
  actions underneath (Screen._modal_binding_chain, not a naive event.stop() — that broke
  TextArea's own undo/redo); $EDITOR is now shell-word-split so multi-word values like
  "code --wait" work; editor saves pass newline="" for portable CRLF correctness

Version 0.5.0 (2026-08-03)
---------------------------
- Command line: a prompt under the panels always shows the active panel's directory; typing
  routes there (not an in-panel filter); cd (quoted paths, ~, bare cd) is intercepted with no
  subprocess spawned, relative targets resolve against the active panel's shown directory
- Execution: anything else runs in a real PTY via App.suspend() — the app hands over the whole
  terminal, so vim, htop, and git rebase -i all get genuine full-screen control; output tees into
  a bounded (100k-line) ring buffer; on return, "Press any key" (skipped when silent) and
  "Exit code: N" for a non-zero exit, then both panels refresh
- Ctrl+O recalls the last command's output in a scrollable view; nothing re-executes
- Code review fix: widened a pre-existing (v0.4) cancellation test's timing margin after it was
  observed flaking under load

Version 0.4.0 (2026-08-03)
---------------------------
- File operations: Copy/Move (F5/F6) — same-filesystem move is an instant rename(), cross-device
  is a verified copy-then-delete; Mkdir (F7) creates a nested a/b/c path in one step; Delete (F8)
  with a confirmation ladder (routine + non-empty-directory + per-read-only-file) and the
  confirm_delete config option now wired; Rename (Shift+F6) in place with the name's stem
  pre-selected
- Every operation runs on a background worker thread with live progress, bytes/files/speed/ETA,
  and a real Cancel button; a six-choice conflict dialog (Overwrite/Skip/Rename/Overwrite All/
  Skip All/Cancel) on any name collision, with "All" answers scoped to one operation
- Code review fix: an unexpected OSError (permission denied, disk full, a vanished source) during
  any file operation now shows a clean error dialog instead of crashing the app
