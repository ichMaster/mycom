# Роадмап — MyCom

> Українська копія [roadmap.md](../roadmap.md). Канонічна версія — англійська; у разі розбіжностей вона має пріоритет.

Дві версії, що будуються по черзі: **v0 — MVP** («відчувається як Far» + по одній wow-функції на кожен AI-модуль) → **v1 — перший публічний реліз** (функції, яких очікує будь-який користувач ортодоксального ФМ, плюс повний AI/агентний шар). Версії нумеруються з 0; фази всередині версії нумеруються `vA.B` (A = версія, B = фаза). Кожна фаза містить **Мету**, короткий опис, список **Задач** і **Definition of Done (DoD)** та постачається з автоматичними тестами, що кодують її DoD (див. [architecture_uk.md](architecture_uk.md) §Тестування і CI).

Обсяг не вигаданий тут: v0 реалізує **Phase 0** зі сканування функціональності FAR, а v1 — **Phase 1**; див. [far-spec/PYTHON_TUI_PRODUCT_SCOPE.md](../far-spec/PYTHON_TUI_PRODUCT_SCOPE.md) (§13, обсяги фаз) і пофункційні критерії приймання в [far-spec/PYTHON_TUI_PHASE0_SPEC.md](../far-spec/PYTHON_TUI_PHASE0_SPEC.md) (функції `F0.x`, на які є посилання нижче). Функції зрілості (Phase 2: фільтри, власні колонки, панелі дерева/інформації, SFTP, API плагінів, AI-перейменування, семантичний пошук, панель перегляду diff, менеджер сесій) специфіковані в [far-spec/PYTHON_TUI_PHASE2_SPEC.md](../far-spec/PYTHON_TUI_PHASE2_SPEC.md) і свідомо не входять у цей роадмап, доки не вийде v1.

**Версіонування (`A.B.C`).** Фаза роадмапу `vA.B` → semver `A.B.0`; пост-релізний фікс фази підіймає `C`. Релізи ріжуться по фазах. Ніколи не підіймати версію без явного підтвердження. Допівотний реліз `0.1.0` (стара концепція) приблизно покриває обсяг нового v0.1, тому ретрофіт v0.1 нижче виходить як `0.1.1`, а перша повністю нова фаза (v0.2) — як `0.2.0`.

**Глобальні критерії приймання (до кожної фази):**
- Кожна функція досяжна лише з клавіатури; миша — опція.
- Жодні дані користувача не втрачаються через невдалу чи скасовану операцію.
- UI ніколи не замерзає: робота > 100 мс іде асинхронно з видимим прогресом.
- Працює в терміналі 80×24; truecolor із відкатом до 256 кольорів.
- Холодний старт < 500 мс до інтерактивних панелей.

## v0 — MVP: «відчувається як Far» + AI-палітра + «Відкрити Claude Code тут»

Планка v0 емоційна, а не лише функціональна: користувач FAR сідає — і його руки вже знають, що робити. Дві панелі з режимами перегляду, сортуванням і виділенням; F5/F6/F7/F8 зі справжнім прогресом і обробкою конфліктів; командний рядок із cd-sync, який чисто запускає vim; переглядач, що миттєво відкриває лог на 1 ГБ; базовий редактор із запасним виходом `$EDITOR`; панель F-клавіш, діалоговий набір, синя тема Far; SQLite-персистентність. Плюс дві wow-функції, які визначають продукт: **AI-палітра команд** (F0.18) і **«Відкрити Claude Code тут»** (F0.19). Усе реалізує критерії приймання `F0.1–F0.19` зі специфікації Phase 0. Залежить від: нічого — це фундамент.

### v0.1 — Ретрофіт ядра панелей

**Мета:** наявний код панелей повністю відповідає критеріям приймання Phase 0 для навігації, режимів перегляду та сортування — і кожна функція реально досяжна з клавіатури.

Допівотна кодова база вже малює дві панелі, навігує, сортує і фільтрує — але обробка клавіш мінімальна, конфіг завантажується і ігнорується, а інтеграційні тести оминають клавіатуру. Ця фаза закриває розрив між «код існує» і «функція працює» (F0.1 навігація, F0.2 колонкові режими, F0.3 сортування) і закладає два фундаменти, які перевикористовує все інше: датакеровану клавіатурну мапу та структуроване логування.

**Задачі:**
- Реєстр клавіатурної мапи: одна структура даних дія → клавіша(і) → контекст, що живить і прив'язки Textual, і (пізніше) панель F-клавіш; накладаються overrides з конфігу `[keybindings]`. Жодних хардкодних клавіш у віджетах.
- Підключити конфіг: `show_hidden`, `default_sort`, `default_sort_direction` течуть у конструювання панелей; видалити мертві шляхи конфігу.
- F0.1: обмін панелей `Ctrl+U` (шляхи, курсори, виділення); курсор стає на дочірню теку при переході вгору; нечитабельна тека (EACCES) → діалог помилки, залишаємось на місці (показати помилку замість теперішньої тихої порожньої панелі).
- Зміна ширини панелей: `Ctrl+Left`/`Ctrl+Right` зсувають розподіл (30/50/70), зберігається зі станом панелі — частина «resize» зі скоупу §1, відсутня в критеріях F0.1; закріплена тут рішенням ([feature-coverage.md](../feature-coverage.md), Part 3).
- F0.2: три режими перегляду — Brief / Full / Wide (`Ctrl+1/2/3`), колонка розміру `<DIR>`, позначення симлінків, обрізання з `…` і повне ім'я в підвалі панелі.
- F0.3: клавіші сортування `Ctrl+F3/F4/F5/F6` з перемиканням напряму, інваріант «теки першими», гліф сортування (`▲`/`▼`) у заголовку; сортування залишається чистою функцією в `operations/sort.py`.
- Структуроване логування (`logging`, рівень/файл через env), підключене на старті застосунку — безцінне для налагодження TUI, дешеве зараз, болюче потім.
- Інтеграційні тести через Pilot: кожна перевірка приймання вище виконується натисканнями клавіш, а не прямими викликами методів.

**DoD:** усі пункти приймання F0.1–F0.3 закриваються при керуванні з клавіатури; тека на 10 000 записів навігується без відчутних лагів; зміни конфігу видимо змінюють поведінку при наступному старті.

**Тести:** unit — резолюція клавіатурної мапи/overrides, чистота сортування (unicode-фікстури), форматування режимів перегляду; інтеграційні (Pilot) — потоки Tab/Ctrl+U/Enter/Backspace, діалог EACCES, відновлення курсора при переході вгору.

### v0.2 — Діалоговий набір, тема Far, панель F-клавіш

**Мета:** один повторно використовуваний модальний рушій і точний вигляд FAR — візуальний та інтеракційний фундамент для всіх наступних фаз.

Реалізує F0.15 (діалоговий рушій і тема) та F0.14 (панель F-клавіш). Палітра вже застосована ad-hoc; ця фаза переносить кожен колір в один файл теми і перебудовує наявні діалоги на наборі.

**Задачі:**
- Діалоговий набір: модальне вікно з рамкою, заголовком, текстом, полями вводу, рядом кнопок; циклювання фокуса `Tab`/стрілками, гарячі літери, `Enter` = кнопка за замовчуванням, `Esc` = скасувати; діалоги стекуються (помилка поверх прогресу).
- Перебудувати `ConfirmDialog` / `InputDialog` / `ProgressDialog` на наборі; аудит: нуль ad-hoc модального коду.
- Файл теми: палітра FAR (з `colormix.cpp`/`palette.cpp`, звірена з живим скриншотом FAR) як єдине джерело кольору — жодних хардкодних кольорів ніде; таблиця відкату до 256 кольорів.
- Панель F-клавіш (F0.14): 10 підписаних слотів, згенерованих із реєстру клавіатурної мапи по контексту (панелі / переглядач / редактор / діалог); непризначені слоти порожні; клік мишею тригерить клавішу.
- Підвал панелі за еталонною розкладкою: кількість елементів, підсумок виділення, місце під вільний простір.

**DoD:** усі діалоги Phase 0 працюють на наборі; підписи панелі F-клавіш генеруються (дрейф неможливий); застосунок коректно рендериться на truecolor і 256-кольорових терміналах.

**Тести:** unit — генерація підписів із мапи, мапінг відкату теми; інтеграційні (Pilot) — порядок фокуса в діалогах, Esc-завжди-безпечно-скасовує, стековані діалоги.

### v0.3 — Модель виділення, приховані файли, SQLite-персистентність

**Мета:** модель виділення, що живить усі файлові операції, плюс стан, який переживає перезапуск.

Реалізує F0.4 (виділення), F0.5 (перемикач прихованих), F0.16 (персистентність). Виділення — вхідний контракт кожної операції F5/F6/F8, тому воно приземляється раніше за них.

**Задачі:**
- Виділення: `Ins` і `Space` перемикають + рухають вниз; `Gray +`/`Gray -` (запасні `Alt+=`/`Alt+-`) — діалоги виділення/зняття за маскою (glob-список, без регістру); `Gray *` (запасна `Alt+8`) — інверсія; «виділити все» — маскою `*` (рішення: без окремої клавіші); `..` ніколи не виділяється; жовтий рендеринг + підвал `N selected (X MB)`.
- Семантика виділення: пер-панельне, переживає зміну сортування/режиму, скидається при зміні теки; операції споживають виділення-інакше-курсор і знімають виділення з оброблених записів при успіху.
- Перемикач прихованих `Ctrl+H`, глобальний, зі збереженням курсора.
- База стану: SQLite (WAL) у платформній теці конфігурації; версіонування схеми + міграції; дебаунс записів, фінальний флаш на виході; пошкоджена/відсутня БД → перестворення, ніколи не блокує старт. Зберігається: шлях панелі, сортування, режим перегляду, перемикач прихованих, стан вікна; таблиці історій створюються (наповнюються у v1).
- Відкат для зниклого шляху панелі: найближчий наявний предок, потім `$HOME`.

**DoD:** потік «виділив 3 — видалив 3» працює наскрізно; перезапуск відновлює шляхи обох панелей, сортування, режим, стан прихованих; kill-9 ніколи не псує БД.

**Тести:** unit — інваріанти виділення (інверсія виключає `..`, правила скидання), збіг масок, міграція БД з порожньої та зі схеми v-1; інтеграційні — round-trip перезапуску, відновлення після kill під час запису.

### v0.4 — Файлові операції

**Мета:** F5/F6/F7/F8 зі справжнім прогресом, скасуванням і обробкою конфліктів — найважчий шматок MVP, зроблений за стандартом FAR.

Реалізує F0.6 (копіювання/переміщення), F0.7 (mkdir), F0.8 (видалення), F0.9 (перейменування), F0.10 (діалог конфліктів). Усі операції виконуються як асинхронні workers над планом задач; UI залишається чуйним; скасування ніколи нічого не псує.

**Задачі:**
- Рушій операцій: обхід → план (кількість, сумарні байти) → виконання у worker з прогресом по файлу і загальним (байти, швидкість, ETA), скасування по `Esc` на межах чанків.
- Копіювання (F5): ціль передзаповнена текою пасивної панелі; рекурсивне; метадані через `shutil.copystat`; симлінки копіюються як симлінки; копіювання на себе/у власну підтеку відхиляється.
- Переміщення (F6): та сама ФС = миттєвий `rename()`; крос-девайс = копія + верифіковане видалення (джерело видаляється лише після повного успіху його копії).
- Mkdir (F7): вкладені `a/b/c`; курсор стає на нову теку.
- Видалення (F8): остаточне, з підтвердженням (сильнішим для непорожніх тек), запит для read-only, прогрес для великих дерев, курсор на наступний вцілілий запис.
- Перейменування (Shift+F6): діалог на місці, основа імені передвиділена; шлях конфліктів спільний із переміщенням.
- Діалог конфліктів (F0.10): розмір/mtime обох файлів із позначкою новішого; Overwrite / Skip / Rename / Overwrite All / Skip All / Cancel; «All» діє в межах операції; тека-на-теку зливаються, файл-на-теку відхиляється.
- Оновлення пасивної панелі по завершенні.

**DoD:** дерево на 1 ГБ копіюється байт-у-байт зі збереженими mtime і живим прогресом; скасоване крос-девайс переміщення залишає джерело неушкодженим; сценарна фікстура на 10 конфліктів коректно проганяє всі шість виборів.

**Тести:** unit — будівник плану, стейт-машина політики конфліктів, детекція тієї самої ФС; інтеграційні — фікстури copy/move/delete/rename, вкл. скасування посеред дерева, видалення read-only, конфлікти злиття (tmpfs-фікстури, без моків).

### v0.5 — Командний рядок, виконання, cd-sync

**Мета:** shell за одне натискання, а панелі завжди слідують за shell — заповіт ортодоксального ФМ.

Реалізує F0.11. Друковані символи набираються в командний рядок (поведінка FAR); `Enter` запускає команду в PTY на повноекранній консольній поверхні, де працюють інтерактивні програми (vim, htop, `git rebase -i`); після виходу панелі повертаються і оновлюються.

**Задачі:**
- Віджет командного рядка під панелями: prompt показує CWD активної панелі; друковані клавіші йдуть сюди, навігаційні залишаються панелі.
- PTY-запускач (passthrough у стилі script): дитина отримує семантику справжнього термінала; вивід tee-каналом іде в кільцевий буфер (безпечний для 100k рядків); `Press any key` на виході (пропускається, коли виводу не було); ненульовий код виходу показується.
- `Ctrl+O`: перемикання панелі / останній консольний вивід.
- Перехоплення `cd` (вкл. `~`, шляхи в лапках): змінює теку активної панелі без підпроцесу; помилки — інлайн.
- cd-sync в обидва боки: навігація панелі оновлює prompt; CWD процесу — завжди тека активної панелі.
- Обидві панелі оновлюють списки після повернення будь-якої зовнішньої команди.

**DoD:** `vim file` чисто повертається до панелей із новим mtime; `cd /tmp` миттєвий і без спавну; команда на 100k рядків не підвішує і не виїдає пам'ять.

**Тести:** unit — парсер cd (лапки, `~`), кільцевий буфер; інтеграційні — сценарні PTY-сесії (неінтерактивні), виклик `Ctrl+O`, показ коду виходу; ручна матриця — vim/htop під tmux і в чистому терміналі на macOS + Linux.

### v0.6 — Переглядач і редактор

**Мета:** `F3` миттєво відкриває будь-що; `F4` редагує безпечно; `$EDITOR` завжди поруч.

Реалізує F0.12 (переглядач) і F0.13 (редактор). Переглядач ніколи не завантажує файл цілком; редактор — Textual `TextArea` із запобіжниками, які роблять його надійним, — і запасним виходом, що тримає обсяг чесним.

**Задачі:**
- Переглядач: віконне читання/mmap; UTF-8 з `errors="replace"`, відкат latin-1; стрілки/PgUp/PgDn/Home/`End`-миттєво-в-кінець; `F2` перемикає перенос зі збереженням позиції; `F6` → редактор; статусбар (ім'я, розмір, зсув, %).
- Редактор: на базі `TextArea`; undo/redo; `F2` зберегти, `Shift+F2` зберегти-як; запобіжник при закритті зі змінами (Save/Discard/Cancel); стиль EOL (LF/CRLF, домінантний у змішаних) визначається і зберігається; збереження хвостового переносу; лише UTF-8, бінарні файли відхиляються → переглядач; >10 МБ перенаправлення → переглядач.
- Запобіжник зовнішніх змін: файл змінено на диску після відкриття → попередження перед збереженням.
- `Alt+F4` відкриває `$EDITOR` (suspend → запуск → resume → refresh); конфіг `editor.external_default` робить це поведінкою `F4`.
- Контексти панелі F-клавіш для переглядача і редактора.

**DoD:** лог на 1 ГБ відкривається < 300 мс з обмеженим RSS; CRLF-файл проходить round-trip без паразитного diff; вихід зі змінами завжди питає; round-trip `$EDITOR` працює в tmux.

**Тести:** unit — детекція/збереження EOL, математика віконної прокрутки, детекція бінарних; інтеграційні — round-trip перегляд/редагування/збереження на фікстурах (величезний файл, CRLF, змішані EOL, бінарний), запобіжник зовнішньої модифікації.

### v0.7 — AI-фундамент: конфігурація провайдера + палітра команд

**Мета:** перша wow-функція — природна мова стає shell-командою, яка ніколи не виконується без явної згоди, — на AI-шарі, якому може довіряти весь продукт.

Реалізує F0.17 (конфігурація провайдера і офлайн-деградація) та F0.18 (AI-палітра команд). Усе проходить крізь шов `LLMClient`; застосунок залишається повністю функціональним без ключа і не генерує жодного мережевого трафіку, доки AI не викликано.

**Задачі:**
- Шов `LLMClient` над Anthropic SDK: стрімінг, адаптивне мислення за замовчуванням, модель із конфігу (за замовчуванням `claude-opus-5`); мокається; ядро ніколи не імпортує SDK напряму.
- Облікові дані: env `ANTHROPIC_API_KEY` → OS keychain (задається командою в застосунку); ніколи не в plaintext-конфігу. Ненаналаштована точка входу AI → одноразовий діалог налаштування, не помилка.
- Офлайн-правило, забезпечене дизайном: жоден AI-об'єкт не конструюється до першого виклику; non-AI сесії чисті під tcpdump.
- Палітра (`Ctrl+Space`): ввід наміру → стрімлена відповідь із запропонованою командою + пояснення в один рядок + рівень небезпеки; надісланий контекст: ОС, shell, CWD, *імена* виділених файлів, обрізаний список — ніколи вміст файлів у v0.
- Евристики небезпеки: рекурсивне видалення, `chmod -R`, `dd`, `sudo`, pipe-в-shell → червона позначка + явне додаткове попередження до можливості Run.
- Дії: Run (через конвеєр v0.5) / Edit (вставити в командний рядок) / Copy / Cancel; помилки API — інлайн, палітра залишається робочою.
- Структурована відповідь для `{command, explanation, danger}` через `output_config.format`.

**DoD:** золотий набір із 10 кейсів (list/find/archive/rename/git) дає команди, що коректно виконуються в контексті панелі; ніщо ніколи не виконується без явного Run; офлайн-виклик деградує до зрозумілої інлайн-помилки.

**Тести:** unit — класифікатор небезпеки, будівник контексту (лапки/пробіли), парсинг структурованої відповіді проти мок-`LLMClient`; інтеграційні — потік палітри з мокнутим стрімінгом (перші токени < 2 с, перевірено фейковим годинником); нуль платних викликів у CI.

## v1 — Перший публічний реліз: планка очікувань ортодоксального ФМ + повний AI-шар

v0 змушує відчути Far; v1 робить продукт *достатньо повним для публікації*: швидкий пошук, підсвічування, меню дисків, автооновлення, смітник, відновлення після помилок, історії, автодоповнення, hex/кодування/пошук/синтаксис у переглядачі й редакторі, пошук файлів, архіви, буфер обміну, меню, теми — а AI-шар виростає з однієї палітри в контекстного асистента (чат-сайдбар, пояснення/підсумовування, розумне виділення, вартісні запобіжники) і справжній хост агента (headless-запуск → вбудовування Agent SDK із TUI-діалогами дозволів). Обсяг: колонка Phase 1 продуктового скоупу (§13). Залежить від: усього v0.

### v1.1 — Рушій файлових масок, швидкий пошук, підсвічування

**Мета:** спільний рушій масок плюс дві функції, які роблять панелі *живими*: стрибок за набором і кольорові групи.

**Задачі:**
- Рушій масок (`*.py,*.md|*test*`, частина виключення): одна реалізація для діалогів виділення, підсвічування, пошуку файлів і (v2) фільтрів; задокументована граматика.
- Швидкий пошук: `Alt+літера` стрибок у панелі, інкрементальний, `Esc`/навігація скидає.
- Групи підсвічування файлів: конфігуровані маска/атрибути → колір (теки білі, виконувані зелені, архіви пурпурові, тимчасові коричневі — дефолти FAR постачаються як дані).
- Доповнення підвалу панелі: вільний простір + сумарні показники теки.
- Перевести діалоги виділення (v0.3) на рушій масок.

**DoD:** підсвічування з коробки збігається з дефолтами FAR і повністю редаговане користувачем; швидкий пошук коректно стрибає в теці на 10k записів; одна реалізація масок обслуговує всіх споживачів.

**Тести:** unit — граматика масок (include/exclude, unicode, правила регістру), пріоритет резолюції підсвічування; інтеграційні — клавіатурні потоки швидкого пошуку.

### v1.2 — Меню дисків, автооновлення, буфер обміну, миша

**Мета:** панель розмовляє із зовнішнім світом: розташування, живі зміни ФС, системний буфер обміну і миша.

**Задачі:**
- Меню дисків/розташувань (`Alt+F1`/`Alt+F2`): точки монтування POSIX + `~` + закладки; диски Windows — за залишковим принципом.
- Автооновлення: спостерігачі `watchdog` на теках обох панелей, з дебаунсом; курсор і виділення зберігаються при оновленнях.
- Буфер обміну: копіювання імен / повних шляхів / вмісту файлів; `pyperclip` з відкатом на OSC 52 для SSH-сесій.
- Миша: клік-фокус, клік-курсор, подвійний клік — вхід, прокрутка колесом, кліки по панелі F-клавіш (у Textual майже безкоштовно — аудит і закриття прогалин).

**DoD:** зовнішні `touch`/`rm` з'являються в панелі протягом секунди без втрати курсора чи виділення; меню розташувань навігує на macOS і Linux; копіювання шляху працює через SSH.

**Тести:** unit — провайдер розташувань по платформах (мокнуті монтування), логіка дебаунсу; інтеграційні — фікстура watchdog (створення/видалення під час сесії), round-trip буфера обміну, де середовище дозволяє.

### v1.3 — Стійкі файлові операції

**Мета:** файлові операції набувають взірцевих манер FAR щодо помилок: смітник, повтор і діалог атрибутів.

**Задачі:**
- Видалення в смітник (`send2trash`) як дефолт `F8`; `Shift+F8` — остаточне; перемикач у конфігу; зміна порівняно з v0 — у реліз-нотах.
- Відновлення після помилок у рушії операцій: збій на файлі → діалог Retry / Skip / Skip All / Cancel, операція коректно продовжується.
- Діалог атрибутів (`Ctrl+A`): POSIX-біти прав + власник (chmod/chown) для курсора чи виділення, рекурсивна опція.
- Верифікувати + закріпити тестами збереження метаданих при копіюванні (mtime, права).

**DoD:** копіювання теки з одним нечитабельним файлом завершується через Skip із точним підсумком; файли зі смітника відновлюються засобами ОС; chmod по виділенню працює рекурсивно.

**Тести:** unit — стейт-машина відновлення, редагування бітів прав; інтеграційні — фікстура EACCES-посеред-копіювання, round-trip смітника, рекурсивний chmod.

### v1.4 — Історії, автодоповнення, зручності командного рядка

**Мета:** командний рядок отримує пам'ять і клавіші м'язової пам'яті, яких очікує кожен користувач FAR.

**Задачі:**
- Персистентні історії в базі стану (команди, теки, переглянуті/редаговані файли, поля діалогів) із закріпленням і пошуком (`Alt+F8` команди, `Alt+F12` теки).
- Tab-доповнення: файли в контексті + команди з PATH.
- `Ctrl+Enter` — вставити ім'я файлу під курсором у командний рядок; `Ctrl+F` — повний шлях.
- Розгортання змінних середовища в командах і шляхах діалогів.
- `Enter` на файлі → відкриття за асоціацією: конфігуровані асоціації (рушій масок) + відкат на типову програму ОС.

**DoD:** історії переживають перезапуск і шукаються; лапки в `Ctrl+Enter` коректні для імен із пробілами; асоціації відкривають правильну програму з відкатом на ОС.

**Тести:** unit — сховище історій (дедуплікація, закріплення, ліміт), кандидати доповнення, резолюція асоціацій; інтеграційні — клавіатурні потоки навігації історією.

### v1.5 — Переглядач і редактор II

**Мета:** переглядач і редактор виростають із MVP у щоденний інструмент: hex, кодування, пошук, підсвічування синтаксису, quick view.

**Тести:** unit — фікстури детекції (utf-8/1251/latin-1/koi8), hex-пошук, заміна з групами; інтеграційні — quick view слідує за курсором, потік меню кодувань.

### v1.7 — Архіви

**DoD:** вхід у zip на 10k елементів миттєвий, елемент переглядається, піддерево розпаковується з прогресом і конфліктами; архів із виділення створюється з байт-коректним вмістом.

**Тести:** unit — мапінг віртуального списку, безпека шляхів (відмова zip-slip); інтеграційні — round-trip перегляд/розпакування/створення на фікстурах.

### v1.9 — AI II: чат-сайдбар, пояснення/підсумовування, розумне виділення, запобіжники

**Мета:** AI-шар стає контекстним і безпечним за вартістю — асистент бачить те, що бачите ви.

**Задачі:**
- Чат-сайдбар: перемикана панель зі стрімленою розмовою; контекст = поточна тека, виділення, переглянутий файл (імена + вміст на вимогу з лімітами розміру); prompt caching для статичного префікса контексту.
- Пояснити/підсумувати: з панелі (файл/тека) або переглядача (поточний файл) → стрім у панель переглядача.
- Розумне виділення: природна мова → предикат виділення через структуровану відповідь (маски + діапазони розміру/дати) з прев'ю перед застосуванням; застосовується через модель виділення v0.3.
- Вартісні запобіжники: preflight `count_tokens` для великих контекстів, пер-сесійний токен-бюджет із видимим лічильником, жорстка зупинка + діалог на межі.
- Усі функції шанують офлайн-правило і шов `LLMClient`.

**DoD:** «виділи всі логи, старші за тиждень» виділяє саме ті файли після прев'ю; підсумовування теки стрімить протягом 2 с; лічильник бюджету зупиняє некеровану сесію на межі.

**Тести:** unit — валідація/компіляція схеми предиката, облік бюджету, ліміти збирання контексту; інтеграційні — потоки сайдбара і розумного виділення проти мок-стрімінгового клієнта; нуль платних викликів у CI.

### v1.10 — Claude Code II: headless-запуск і вбудовування Agent SDK

**Мета:** від «відкрити термінал для агента» до «агент — повноправний громадянин файлового менеджера» — ця фаза і є публічний реліз.

**Задачі:**
- Headless-запуск: `claude -p "<задача>"` на виділенні/CWD з `--output-format stream-json`; живий прогрес у панелі задач; результат у переглядач; скасування вбиває групу процесів.
- Вбудовування Agent SDK (`claude-agent-sdk`): поле запиту → сесія агента в активній теці; стрімлена панель транскрипту (текст асистента, виклики інструментів, результати).
- Діалоги дозволів: permission-колбеки SDK показуються як діалоги набору (дозволити / відхилити з повідомленням), шануючи принцип «підтвердження перед запуском»; «завжди дозволяти» в межах сесії.
- Передача контексту: виділені файли / стан панелей інжектяться в запит сесії.
- Панелі автооновлюються (спостерігачі v1.2), поки агент редагує — сама панель live-diff залишається у v2.
- Реліз-інженерія: пакування на PyPI, шлях встановлення `pipx`/`uv tool`, оновлення README + сайту документації → **перший публічний реліз**.

**DoD:** headless-задача стрімить прогрес і кладе результат у переглядач; вбудована сесія редагує файли лише після TUI-схвалення, панелі оновлюються наживо; `uv tool install mycom` працює на чистій машині.

**Тести:** unit — парсер stream-json, місток permission-колбеків, інжекція контексту; інтеграційні — сценарна SDK-сесія з мок-транспортом, що проганяє повну матрицю approve/deny; ручні — справжня наскрізна сесія агента на macOS + Linux.
