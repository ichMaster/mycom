# v0.3 — GitHub Issues

Issues for phase **v0.3 — Selection model, hidden files, SQLite persistence** (version **v0 —
MVP**), derived from the per-phase Tasks in [roadmap.md](../../roadmap.md) (§v0.3) and the
components in [architecture.md](../../../spec/architecture.md) (Panels, Filesystem layer, State).
This file is scoped to a single phase; IDs continue from v0.2 (MC-018 → **MC-019…MC-024**).

Selection is the input contract every F5/F6/F8 operation will consume in v0.4, so it lands first.
`mycom/state.py` does not exist yet — this phase creates it. `FileBrowserPanel` already has the
`show_hidden` flag from v0.1's config wiring, but only as a startup value; this phase makes it a
live, global, `Ctrl+H`-driven toggle. Panel resize (v0.1) and view mode (v0.1) are currently
in-memory only with a documented "deferred to v0.3" caveat — this phase closes that gap too.

## v0.3 — Selection model, hidden files, SQLite persistence

### MC-019 — Selection model core: Ins/Space, yellow rows, footer count, per-panel lifecycle

**Description:**
The input contract every file operation (F5/F6/F8, v0.4) will consume: a per-panel set of
selected names, toggled by `Ins`/`Space`, rendered in yellow, summarized in the footer, surviving
sort/view-mode changes but resetting on directory change. `..` can never be selected.

**What needs to be done:**
- `mycom/keymap.py`: `Command("select_toggle", ("insert", "space"), "panel", "Select")`.
- `FileBrowserPanel`: a `_selected: set[str]` (names, per-panel instance state — not per-directory,
  since it resets on navigation per the acceptance criteria below). `action_select_toggle`
  (`MyComApp`) calls `panel.toggle_selection_at_cursor()`: toggles the cursor entry's name in
  `_selected` (no-op on `..`), moves the cursor down one row (`FileList` gains a
  `move_cursor_down()` helper — reuse `DataTable.action_cursor_down()` if it fits), re-renders.
- `FileList`/`_load_columns`/`_load_brief`: selected entries render their name (and Brief-mode
  grid cell) wrapped in `[{SELECTED_FG}]...[/]` Rich markup (import the hex constant from
  `mycom/theme.py` — Rich markup needs a literal color, not a `$css-variable`) so they show yellow
  regardless of view mode; needs the current `_selected` set threaded from `FileBrowserPanel` into
  `FileList.load_directory`/rebuild calls.
- `_update_footer`: replace the `"0 selected"` placeholder (v0.2) with
  `f"{n} selected ({format_size(total_bytes)})"` when `_selected` is non-empty, else keep
  `"0 selected"`.
- Lifecycle: `refresh_listing()` (sort/view-mode changes go through this) preserves `_selected`
  unchanged; `navigate_to()`/`navigate_up()` clear `_selected` on a successful directory change.
- `FileBrowserPanel.get_selected_files() -> list[Path]`: returns the selection (resolved to full
  paths) if non-empty, else `[cursor file]` if any — this is "selection-else-cursor", the contract
  v0.4's operations consume. `FileBrowserPanel.deselect(names: Iterable[str]) -> None`: removes
  the given names from `_selected` — the "deselect processed entries on success" contract v0.4
  will call after a successful operation (no real operation exists yet to call it, so this issue's
  test exercises the method directly, not through a stubbed F8).

**Dependencies:** None

**Expected result:**
`Ins`/`Space` build up a per-panel selection that's visually yellow, counted in the footer, stable
across sort/view changes, and gone after navigating elsewhere; the API surface v0.4 needs already
exists and is tested.

**Acceptance criteria:**
- [ ] `Ins` and `Space` both toggle the cursor entry and move the cursor down one row.
- [ ] `..` is never selectable (toggling on the `..` row is a no-op).
- [ ] Selected rows render in `$selected-fg` yellow in all three view modes.
- [ ] Footer shows `"{n} selected ({size})"` when non-empty, `"0 selected"` when empty.
- [ ] Selection survives `Ctrl+F3`–`F6` (sort) and `Ctrl+1/2/3` (view mode); selection is empty
      again after `navigate_to`/`navigate_up` succeeds.
- [ ] `get_selected_files()` returns the selection when non-empty, else `[cursor]`;
      `deselect(names)` removes exactly those names.
- [ ] **Unit test:** selection invariants (`..` unselectable, reset-on-navigate, survive-sort/view).
- [ ] **Pilot test:** `Ins`/`Space` toggle-and-advance flow; footer text after selecting 3 files.

### MC-020 — Mask select/deselect dialogs

**Description:**
`Gray +`/`Gray -` (fallback `Alt+=`/`Alt+-`) open a select/deselect-by-mask dialog: one input,
`Enter` applies, `Esc` cancels — reusing v0.2's `InputDialog` as-is (its shape already matches
F0.4's "single input field, Enter=apply, Esc=cancel" UI spec exactly). Matching is a minimal
case-insensitive glob-list ("`*.py;*.md`" — semicolon **or** comma separated), deliberately not
the full masks grammar (exclude parts, `|`) that v1.1 generalizes into one shared masks engine
this dialog will later retrofit onto.

**What needs to be done:**
- `mycom/keymap.py`: `Command("select_mask", ("+", "alt+equals_sign"), "panel", "Select")`,
  `Command("deselect_mask", ("-", "alt+minus"), "panel", "Deselect")`.
- `mycom/utils/masks.py` (new, small, pure — the seam v1.1 replaces):
  `match_any(name: str, pattern_list: str) -> bool`, splitting on `;`/`,`, case-insensitive
  `fnmatch.fnmatch` per pattern, empty/whitespace-only pattern list matches nothing.
- `MyComApp.action_select_mask`/`action_deselect_mask`: open `InputDialog("Select files matching
  (e.g. *.py;*.md):", default="*")` / the deselect equivalent; on a non-`None`, non-empty result,
  call a new `FileBrowserPanel.select_by_mask(pattern, select: bool)` that applies `match_any`
  against every non-`..` entry in the current listing, adding to (select=True) or removing from
  (select=False) `_selected`, then re-renders.

**Dependencies:** MC-019

**Expected result:**
`+`/`Alt+=` and `-`/`Alt+-` open a mask prompt; applying `*.py` selects/deselects exactly the
matching files, case-insensitively.

**Acceptance criteria:**
- [ ] `+` with `*.py` selects exactly the `.py` files in the current listing (case-insensitive).
- [ ] `*.py;*.md` selects both extensions; `-` with the same pattern deselects them.
- [ ] Cancelling the dialog (`Esc`) leaves the selection unchanged.
- [ ] **Unit test:** `match_any` — single pattern, multi-pattern (`;` and `,`), case-insensitivity,
      empty pattern list.
- [ ] **Pilot test:** `+` opens the dialog, typing `*.py` + `Enter` selects the right files.

### MC-021 — Invert selection + select-all via mask

**Description:**
`Gray *` (fallback `Alt+8`) inverts the current selection. Select-all is **not** a separate key —
per roadmap decision, it's just mask-select with pattern `*` (MC-020's dialog already does this
with no new code).

**What needs to be done:**
- `mycom/keymap.py`: `Command("select_invert", ("*", "alt+8"), "panel", "Invert")`.
- `FileBrowserPanel.invert_selection()`: for every non-`..` entry in the current listing, flip its
  membership in `_selected` (selected → deselected, not-selected → selected); `..` is never
  touched (already unselectable, so inversion can't select it either way).
- `MyComApp.action_select_invert` wires the key to it.
- No new UI for select-all: confirm (via a test, not new code) that opening MC-020's mask dialog
  with the default pre-filled `"*"` and pressing `Enter` immediately selects everything.

**Dependencies:** MC-020

**Expected result:**
`*`/`Alt+8` inverts the selection; `+` with the default `*` pattern selects everything without a
dedicated select-all key.

**Acceptance criteria:**
- [ ] Inverting a selection of 2 out of 5 files selects the other 3 and deselects the original 2.
- [ ] Invert on an empty selection selects everything (all non-`..` entries); invert on a full
      selection clears it.
- [ ] Invert never selects `..`.
- [ ] `+` then `Enter` (default pattern `*`) selects every non-`..` entry — the select-all path.
- [ ] **Unit test:** invert invariants (excludes `..`, empty↔full round trip).
- [ ] **Pilot test:** `*` inverts a partial selection; `+`/`Enter` selects all.

### MC-022 — Ctrl+H global hidden-files toggle

**Description:**
`Ctrl+H` toggles hidden-file visibility globally (both panels at once), cursor-preserving. v0.1
already wired `show_hidden` from config into panel construction as a one-time startup value; this
makes it a live, app-wide toggle.

**What needs to be done:**
- `mycom/keymap.py`: `Command("toggle_hidden", ("ctrl+h",), "panel", "Hidden")`.
- `FileBrowserPanel.set_show_hidden(value: bool) -> None`: updates `self._show_hidden`, remembers
  the cursor's current name, calls `refresh_listing()`, then `select_by_name(name)` (existing
  helper — falls back to row 0, satisfying "moves to nearest neighbor" when the file is no longer
  visible).
- `MyComApp.action_toggle_hidden`: flips one app-level `self._show_hidden` bool, calls
  `set_show_hidden` on **both** panels (global, not per-panel), so both update in the same
  keypress.

**Dependencies:** MC-019

**Expected result:**
`Ctrl+H` shows/hides dotfiles in both panels simultaneously; the cursor stays put when possible.

**Acceptance criteria:**
- [ ] `Ctrl+H` toggles hidden-file visibility in both panels from a single keypress.
- [ ] Cursor stays on the same file after toggling if it's still visible; otherwise falls back to
      the first row.
- [ ] **Pilot test:** toggle shows/hides a `.hidden` fixture file in both panels; cursor-preserve
      and cursor-fallback cases.

### MC-023 — State DB engine: SQLite (WAL), schema, migrations, corrupt-recreate

**Description:**
`mycom/state.py` (declared in `spec/architecture.md`'s package layout, doesn't exist yet): one
SQLite database at the platform config dir, WAL mode, schema-versioned with migrations, corrupt
or missing DB recreates silently rather than blocking startup. Pure engine in this issue — nothing
wired into the app yet (MC-024).

**What needs to be done:**
- `mycom/state.py`: `StateDB` class wrapping a `sqlite3.Connection` opened at
  `~/.config/mycom/state.db` (platform config dir, matching `mycom/config.py`'s `CONFIG_DIR`),
  `PRAGMA journal_mode=WAL`.
- Schema v1: `schema_version` table (single row); `panel_state` (`side TEXT PRIMARY KEY, path
  TEXT, sort_field TEXT, sort_ascending INTEGER, view_mode TEXT`); `app_state` (`key TEXT PRIMARY
  KEY, value TEXT`) for the global hidden-toggle and window state (active side, resize index);
  empty `command_history`/`folder_history` tables created now, filled starting v1.4 per
  architecture.md.
- Migration runner: `_migrate(conn)` applies numbered migrations in order from the DB's current
  `schema_version` up to the latest; starting from empty (fresh file) runs all of them.
- Corrupt/missing DB handling: opening a file that isn't a valid SQLite DB (or fails a basic
  integrity check) logs a warning and recreates it from scratch rather than raising — startup must
  never be blocked by state.
- `get_panel_state(side) -> PanelState | None`, `save_panel_state(side, ...)`,
  `get_app_state(key, default=None)`, `save_app_state(key, value)` — simple typed accessors; no
  Textual dependency, fully unit-testable in isolation with tmp DB files.

**Dependencies:** None

**Expected result:**
A reusable, tested persistence engine — WAL, versioned schema, safe on corruption — ready for
MC-024 to wire into the app lifecycle.

**Acceptance criteria:**
- [ ] Fresh DB file: schema created, `schema_version` at the latest version.
- [ ] `save_panel_state`/`get_panel_state` round-trip correctly.
- [ ] A DB file containing garbage bytes (not valid SQLite) is detected and recreated, not raised.
- [ ] WAL mode confirmed active (`PRAGMA journal_mode` returns `wal`).
- [ ] **Unit test:** fresh-DB creation, round-trip accessors, corrupt-file recreation, migration
      from an empty/v0 schema to v1 (tmp-path DB files, no real `~/.config` writes in tests).

### MC-024 — Wire persistence into app lifecycle

**Description:**
Connect `mycom/state.py` (MC-023) to `MyComApp`: restore both panels' paths/sort/view and the
global hidden toggle at startup (with a fallback for a panel path that no longer exists), save on
relevant changes with debouncing, flush once on exit.

**What needs to be done:**
- `MyComApp.__init__`/`compose`: open a `StateDB`; on startup, read `panel_state` for `"left"`/
  `"right"` and `app_state["show_hidden"]`/window state, and construct panels from the restored
  values instead of always `Path.cwd()` + config defaults (config-file defaults still apply on
  first run / when no saved state exists yet — state DB wins once it has data, matching "restart
  restores... " DoD).
- Vanished-path fallback: if a restored panel path no longer exists (or isn't a directory),
  `FileBrowserPanel`'s startup path resolution walks up (`path.parent`, repeatedly) to the nearest
  existing ancestor, falling back to `Path.home()` if nothing along the chain exists.
- Debounced save: a small `_schedule_save()` on `MyComApp` using Textual's `set_timer`
  (cancel-and-reset pattern, ~500 ms) triggered after navigation, sort, view-mode, resize, and
  hidden-toggle changes; writes both panels' current path/sort/view and the app-level hidden/
  window state.
- Flush on exit: override `MyComApp.action_quit` to cancel any pending debounce timer and write
  the current state synchronously before calling `super().action_quit()`.
- `spec/architecture.md` already documents this seam (§Persistence, package layout) — no doc
  change needed, this issue implements what's specified there.

**Dependencies:** MC-023, MC-019, MC-022

**Expected result:**
A restart brings both panels back to where they were — path, sort, view, hidden toggle — and a
vanished path degrades gracefully instead of crashing or silently defaulting to `cwd`.

**Acceptance criteria:**
- [ ] Restart after navigating/sorting/changing view/toggling hidden restores all of it, both
      panels.
- [ ] A panel whose saved path was deleted falls back to the nearest existing ancestor, then
      `$HOME`, without error.
- [ ] `kill -9` mid-session (simulated: no clean shutdown) loses at most the last debounce window
      of state, never corrupts the DB (WAL survives).
- [ ] Deleting `state.db` entirely yields clean startup with config-file defaults, no crash.
- [ ] **Integration test:** build an `MyComApp`, mutate state (navigate/sort/hidden), construct a
      **second** `MyComApp` instance against the same DB path, assert it restores the same state
      (a same-process restart simulation, since a real subprocess restart isn't practical in the
      test suite).
