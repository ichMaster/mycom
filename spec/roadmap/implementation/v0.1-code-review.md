## Findings

### 1. 🟠 Vanished/replaced directory still renders silently empty

**Files:** `mycom/utils/fs.py:66-71`, `mycom/panels/file_browser.py` (`navigate_to`/`refresh_listing`)

**Failure scenario:** `list_directory(path, strict=True)` re-raises only `PermissionError`; every
other `OSError` (`FileNotFoundError`/ENOENT when a directory is removed between selection and
`Enter`, `NotADirectoryError` if replaced by a file) still hits the blanket
`except OSError: return []`. `FileBrowserPanel.navigate_to`/`refresh_listing` only catch
`PermissionError`, so the panel commits to the phantom path and shows "0 items, no dialog" — the
exact silent-empty-panel anti-pattern F0.1's EACCES fix was supposed to close, just for a different
errno.

**Fix:** `list_directory`'s strict mode now re-raises any `OSError` encountered while opening the
target directory itself (not per-entry stat failures inside the loop, which stay lenient as
before); `FileBrowserPanel` catches `OSError` instead of `PermissionError` in both `navigate_to`
and `refresh_listing`, showing `f"Cannot open {path}: {exc}"` and staying on the previous path.

### 2. 🟠 `_show_error`'s unmounted-widget guard is dead code

**File:** `mycom/panels/file_browser.py` (`_show_error`)

**Failure scenario:** `if self.app is not None:` never protects anything — Textual's `Widget.app`
property raises `NoActiveAppError` on an unmounted widget rather than returning `None`. Verified
live: `FileBrowserPanel(...).navigate_to(<eacces dir>)` on a panel constructed outside a running
`App` (a pattern this codebase's own tests already use, e.g.
`tests/unit/test_app_config_wiring.py::test_invalid_default_sort_falls_back_to_name`) crashes with
`NoActiveAppError` instead of safely no-op'ing. Not reachable through the shipped keyboard flow
(panels are always mounted before use in `MyComApp`), but a live trap for future direct-construction
tests or refactors.

**Fix:** guard on `self.is_mounted` instead of the never-true `self.app is not None` check.

### 3. 🟠 Panel resize doesn't follow Tab focus switch

**File:** `mycom/app.py` (`action_switch_panel`)

**Failure scenario:** `Ctrl+Right` sets `active_panel.styles.width = "70%"` /
`inactive_panel.styles.width = "1fr"` at press-time only. Verified live: `Ctrl+Right` then `Tab`
leaves the **old** active panel at 70% and the **new** active panel at `1fr` — the visually-wide
panel no longer matches the actually-active one until another resize key is pressed. This breaks
the resize feature's own contract ("cycle **the active panel's** width") the moment focus moves.

**Fix:** `action_switch_panel` now calls `self._apply_panel_widths()` after flipping
`_active_side`, so the width always follows whichever panel is active.

### 4. 🟡 Brief-mode column count is stale after a live resize (DEFERRED)

**File:** `mycom/widgets/file_list.py` (`_rebuild_columns`)

**Failure scenario:** column count is computed only in `on_mount`/`set_view_mode`/
`set_sort_indicator`, not on an `on_resize` event. Verified live: Brief mode at panel width 58
computes 2 columns; growing the panel to width 82 via `Ctrl+Right` leaves it at 2 (should reflow to
3). Purely cosmetic — the index math stays internally consistent (no crash, no wrong selection),
the layout just isn't maximally packed until the next view-mode or sort change forces a rebuild.

**Why deferred:** a correct fix needs a **debounced** `on_resize` handler — Textual fires resize
events frequently during interactive terminal resizing, and `_rebuild_columns` calls
`self.clear(columns=True)`, so an undebounced hook would thrash-rebuild the whole grid on every
tick. That's a small design decision (debounce interval, whether to reload entries synchronously
or via a timer), not a one-line fix-now change. No roadmap phase owns "live column reflow"
explicitly — parking it as opportunistic polish; revisit if real usage flags it as annoying rather
than pre-emptively engineering a debounce nobody asked for yet.

### 5. 🟡 `truncate_name` splits by codepoint, not grapheme cluster (DEFERRED)

**File:** `mycom/widgets/file_list.py` (`truncate_name`)

**Failure scenario:** truncation counts Unicode codepoints, not grapheme clusters. Verified live:
`truncate_name("👨‍👩‍👧‍👦.txt", 3)` → a family emoji built from 4 codepoints + 3 zero-width
joiners produces a dangling ZWJ stranded right before the "…". Cosmetic only (no crash, no data
corruption — the underlying `FileEntry.name` is never touched, only the *displayed* truncated
string), but it's short of the issue's own "doesn't split a multi-byte grapheme" bar; the shipped
unit test only exercises single-codepoint CJK names, so it didn't catch this.

**Why deferred:** correct grapheme-cluster segmentation needs either the `regex` package's `\X`
matcher (a new dependency, not currently in `pyproject.toml`) or a hand-rolled ZWJ/combining-mark
scanner — real but non-trivial work for a cosmetic edge case (multi-codepoint emoji in filenames).
Documented as MVP scope: codepoint-level truncation is what v0.1 ships; revisit with a proper
grapheme-aware helper if real-world filenames make this bite (natural fit alongside the encoding
work in v1.5).

## What's solid

- The `on_key`-vs-`App.bind` split for the three widget-intercepting actions (`switch_panel`,
  `open`, `go_up`) is correct — verified Tab and Ctrl+U live against a focused `DataTable`.
- No single-writer-rule violations: v0.1 introduces no threads/workers, so there's nothing yet to
  violate the marshal-back-to-the-loop discipline.
- The EACCES-in-the-normal-flow path (the case the phase was built to fix) is correct: path and
  entries stay untouched, the dialog appears, and dismissing it leaves the panel exactly where it
  was.
- Entering on a Brief-mode padding cell (past the last real entry in a partially-filled row) returns
  `None` from `selected_name` safely — no crash, no phantom navigation.
- `logging_setup.configure_logging()`'s handler dedup is correctly idempotent across repeated calls
  (verified against its own test).
- The `".."` rename from the old `"__parent__"` sentinel can't collide with a real entry: every real
  Brief-grid name is `icon + filename` where `icon` is one of `\`, `~`, or a space — none of which
  is `.`, so `icon + name` can never equal the literal `".."`.
- `SORT_FIELDS` fallback-with-warning logic uses correct `%`-style logging args (no premature
  string interpolation).
